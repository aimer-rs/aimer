# 26.0.0-dev.2

Changes since `26.0.0-dev.1`.

## New Features

### Shortcuts

- **Local shortcuts** with the `Shortcuts` widget (`aimer::shortcut`). Chords such as `"CmdOrCtrl+K"` or `F5` run an action while focus is inside the subtree, the innermost scope wins, and `.window(true)` makes a scope active wherever focus is. Nothing is checked until the first scope exists, so apps that do not use shortcuts pay nothing.
- **Application menu** with `aimer::shortcut::menu`. Describe the menus once with `AppMenu`: macOS builds a native menu with the shortcut shown beside each item, and every other platform runs the same chords as window-wide shortcuts.
- **Global shortcuts** with `GlobalShortcut`, which fire while the app is in the background: Carbon hot keys on macOS, `RegisterHotKey` on Windows and X11 key grabs on Linux. Wayland, iOS, Android and web report `Unsupported`.
    - Only the macOS backend has been run. The Windows and Linux backends are compile-checked only.
- The **Shortcuts** page in the Jaime showcase (and `cargo run -p aimer --example shortcuts`) shows all three kinds and logs what fires.

### Windows

- **Frosted windows** with the `WindowBackdrop` widget (`aimer::WindowBackdrop`, `aimer::WindowMaterial`). Wrap a window's content in it and the system blurs the desktop and the windows behind it through everything the content draws with some transparency, like a Finder sidebar. The blur is drawn by the system, and the window is restored when the widget leaves the tree. See `cargo run -p aimer --example window_backdrop`.
    - `WindowMaterial::Glass` and `WindowMaterial::ClearGlass` give the refractive Liquid Glass look of macOS 26 and later through an `NSGlassEffectView`, falling back to the sidebar blur on older systems. Jaime's sidebar uses `Glass`.
    - macOS uses an `NSVisualEffectView` and has been run. Windows asks DWM for a Mica or Acrylic backdrop and is compile-checked only; the Windows renderer's swap chain ignores alpha, so the backdrop may not show through there yet. Other platforms ignore the widget.

### Media

- **Audio** playback on macOS and iOS, with Android, Windows, Linux and web backends. Remote audio streams while it downloads, and the seek bar is draggable.
- **Video** playback with zero-copy frames on macOS and iOS, plus backends for Windows (MediaPlayer frames as shared D3D textures) and web (copied from an `HTMLVideoElement`).
    - Linux and Android not have been finished yet
- A standard **video player** widget with captions, chapters and fullscreen.
- **GIF** support in assets.
- **Lottie** animation support.
- **Haptic feedback** for macOS and Android.
- **System notifications** with `aimer::notification` (`aimer_notification`). Show, replace, schedule and close a notification with a title, subtitle, body, sound and buttons, ask for the permission, and hear clicks, buttons and dismissals on the event loop through `notification::install`. macOS and iOS use `UNUserNotificationCenter`, Linux the freedesktop D-Bus service, Windows a notification-area balloon and Android `NotificationManager`. Push is client side: `Notifier::register_push` asks for a token and launcher glue reports it through `notification::push`. In-window messages remain the toasts in `aimer::feedback`.
- **Live activities** with `aimer::live_activity` (`aimer_live_activity`, feature `live-activity`). `LiveActivities::show` starts or updates, and `end` ends, one glanceable activity described by a title, body, short status, progress, milestones, an icon and optional custom state. Android posts a Live Update (`Notification.ProgressStyle` with a promoted-ongoing request on Android 16, an ongoing progress notification before). iOS 16.2+ drives ActivityKit through a Swift bridge the app ships, found with `dlsym` so an app without it still links, plus a live-activity-only widget extension in SwiftUI; the custom state is readable by a custom SwiftUI view and ignored elsewhere. macOS (whose SDK marks ActivityKit unavailable), Windows and Linux report `Unsupported` unless the app opts in to a tray icon with `LiveActivitiesBuilder::tray_icon`.
    - Only the portable model, the JSON contract with Swift and the tray bookkeeping have run. The Android backend is compile-checked, and the Swift files are type-checked against the iOS SDK; none of them has run on a device.
    - `LiveActivity::countdown` gives an activity a deadline the system ticks by itself, so the clock on the Dynamic Island, the lock screen and the Android chip keeps moving while the app is suspended in the background (`Text(timerInterval:)` and `ProgressView(timerInterval:)` on iOS, a count-down chronometer on Android). Before, text pushed from the app froze as soon as the app went away. Projects whose widget Swift was generated earlier keep their copy: take the new `AimerLiveActivityAttributes.swift` and `AimerLiveActivityWidget.swift` from `native/live_activity/swift`.
    - `UIKitWidget` describes views for the Dynamic Island and the lock screen as data, and `LiveActivity::view(Region, widget)` fills one slot of the island or the lock screen with it. It is deliberately not an Aimer `Widget`, so it cannot be placed in an Aimer tree. The built-in `Label`, `Symbol`, `Bar`, `Clock`, `Row`, `Column` and `Gap` are drawn by a generic SwiftUI interpreter in the widget extension, and the clock and bar follow the system-ticked countdown. Android and the tray ignore views. Projects whose widget Swift was generated earlier must take the new `AimerLiveActivityAttributes.swift` and `AimerLiveActivityWidget.swift` from `native/live_activity/swift`.
    - The Jaime showcase has a **Live activity timer** page: set a timeout with the plus and minus buttons, start it, and the time left is mirrored in a live activity (a Venus task ticks once a second, so it works on every platform).

### Graphics and shaders

- Public **shader effects**, a **shader transpiler**, and a `ShaderEffectDecoration`.
- `CustomPaint` for drawing directly on a canvas.
- `bulge_radius` and bevel width options on `Magnification`.

### Layout and widgets

- **A code-editor surface** for `TextArea`, for apps that edit code:
    - `.wrap(false)` shows each line on one row, however long, and scrolls sideways to the caret, with the trackpad, and with `Shift` and the wheel. It works for long texts laid out as a window, too.
    - `.line_numbers(LineNumbers::new()...)` draws a margin of line numbers beside the text, right-aligned, one per line (a wrapped line has its number once), with the caret's line in its own color. The margin widens with the number of digits, and a click in it puts the caret at the start of the line.
    - `.current_line(color)` draws a band behind the line the caret is on, across the margin and the text.
    - `TextEditingController::cursor_position()` (the one-based line and column, as a status bar shows them), `line_count()`, `select(anchor, focus)`, and `listen(callback)`, which calls back after every change to the text or the caret, until its guard is dropped.
    - `TextArea::gutter_markers(GutterMarkers)`: a column of clickable icons before the line numbers (`GutterMarker` is an SVG scene and a press handler, asked for per line, drawn from the line's first row, and a press on one calls its handler without moving the caret).
    - In a `TextArea` with embeds, the line number and the gutter marker of a row an embedded widget stands in for are drawn at the top of the row (the widget's first line) and not down on its baseline, and the current-line band is not drawn for a caret inside an embed.
    - `TextArea::line_break_prefix(|line_before_caret| Option<String>)`: Return starts the new line with what the callback returns, so a code editor can continue a `///` comment or a list.
    - `TextArea::line_bars(LineBars)`: a colored bar down the left of chosen lines, behind the text, asked for per line with the `HighlightContext` the text is styled with, so it can follow the caret like a highlighter does. Each row of a line gets its bar, so a run of lines is one rule; bars scroll sideways with the text.
    - The line numbers of a `TextArea` are placed row by row, each on the baseline of its own line, instead of as one block of text with rows of one height: a taller line (a rendered heading) no longer pushes the numbers after it off their lines.
    - Fixed a text area snapping back to its caret whenever its window was resized, activated again or relaid out (full screen in and out), which undid the wheel: a field inside a selection area re-armed "scroll to the caret" on every layout pass while the area held a selection, even when the area said what the field already had. It now acts, and asks for the caret to be shown, only when the area moves the caret. Gaining focus no longer asks for it either: a click, a key, an edit and a field's first layout still do.
    - Fixed a windowed text (over 64 KB) in a `TextArea` that fills its height (`expand(true)`) painting nothing past its first screenful: the window of laid-out lines was chosen as if a parent scrolled the field, and so stayed at the top of the text however far the field was scrolled, or the window resized (full screen in and out).
    - Fixed a panic (`RefCell already borrowed`) when the last callback of a `TextEditingController::listen` listener was released by dropping another listener: the attachment's drop now releases the old callback list after the controller's state is no longer borrowed.
    - `TextEditingValue::write_to(writer)` writes the text a piece at a time, so a file of megabytes is saved from the chunks it is in and no `String` is made of it, and `TextEditingValue::snapshot()` and `TextEditingController::snapshot()` are public.
    - `TextSnapshot::bytes_from(offset)` reads the text a chunk at a time from any offset, which is what a parser such as tree-sitter wants, so a file is parsed straight out of the editor's rope. `SpanStyle` and `StyledRange` can be compared.
- **Editor keys** in `TextField` and `TextArea`, as most text editors have them: `Home` and `End` go to the start and end of the visual line (where a long line wraps, or the hard line it is on) and, with `Ctrl` or `Cmd`, of the text; `Option`+arrows on macOS and `Ctrl`+arrows elsewhere move by word, and `Cmd`+Left/Right, Up/Down on macOS go to the ends of the line and of the text; the same with `Shift` extends the selection. `Option`/`Ctrl`+`Backspace` and `Delete` delete a word, and `Cmd`+`Backspace`/`Delete` on macOS delete to the start or end of the line, each as one undo step, or delete the selection if there is one. `PageUp` and `PageDown` move the caret a page in a field that scrolls inside itself; a field its parent scrolls leaves them to the parent. Long texts work the same. **Breaking:** `Home` and `End` used to go to the ends of the whole text; that is now `Ctrl`/`Cmd`+`Home`/`End`.
- **Shift-click selection** in `TextField` and `TextArea`: holding shift while pressing the mouse extends the selection from its anchor (or from the caret, when nothing is selected) to where the pointer lands, and dragging on continues it. It is not counted as part of a double or triple click, and touch is unchanged. Pointer events carry no modifiers, so `Modifiers::current()` (`aimer::events::element`) now answers which keys are held, as the event loop last saw them, for any widget that needs it.

- **Windowed styling** with `TextHighlighter::windowed` and `TextEmbedder::windowed` (`aimer::input`): the function receives the text as a `TextSnapshot` and the byte range the field is about to lay out, and styles or embeds only that, so styling a long text costs what is on screen. `HighlightContext::in_snapshot` finds the cursor's lines from the snapshot's line counts. A field with a short text, and `highlight`, ask for the whole text at once.
    - `LivePreview` reads a note of 256 KB or more this way. A link reference or footnote definition is then found only by the piece it is in (a shorter note is read whole, as before).

- `Center`, a lightweight widget for centering a single child.
- **Reverse mode** for `Scrollable`, for end-anchored content such as chat.
- Drag-to-scroll on the scroll track and thumb.
- **Accessibility** support.
- **Hinge and fold** support on iOS.
- `.px()` and `.pc()` sugar on numbers.

### Stateful widgets

The stateful widget API was reworked; see **Breaking** under Changes for the migration.

- **A state no longer stores its own updater.** `build` receives a `StateView`, which derefs to the state, so fields are read directly (`this.count`), and `this.updater()` is the `Copy`, `'static` handle that callbacks use. The "add this line to `init_state`" panic for a forgotten `self.updater = updater` is gone with the field.
- **The state type can be private.** It is named by `#[state(MyState)]` on the widget and only inside the body of the derived `to_element`, never in a signature, so it no longer has to be `pub` (it used to fail with E0446).
- **`init_state(&mut self)` is optional and plain.** It runs once, before the first build, and mutates the state directly.
- **`on_mount(&mut self, updater)`** runs right after `init_state` and hands the state its `StateUpdater`, for registering something that has to reach back into it later: a back or link handler, a subscription, a repaint callback.
- **`StateUpdater::mounted()` and `StateView::mounted()`** tell a callback whether its widget is still in the tree. Use it before touching the state from a timer, a request or a task that can outlive the element. It is the same quiet check as `has_state()`.

    ```rust
    let updater = this.updater();
    spawn(async move {
        let data = fetch().await;
        if updater.mounted() {
            updater.set_state(move |state| state.data = Some(data));
        }
    });
    ```

- **Compile-time protection.** Capturing `this` in a `'static` closure does not compile, so a handler cannot read a stale reference. A handler that has to read the state when it runs takes `this.updater()` and uses `read` or `try_read`.
- For tests: `widget.create_state::<MyState>()`, `state.build_element(&ctx)` and `StateView::detached` (all `#[doc(hidden)]`) build a state without mounting it.

### Venus

- Added `spawn`: spawns a `!Send` future as a microtask that runs before the next build phase.
- Added `join!`: polls several futures together inside the awaiting task and returns all outputs as a tuple. Nothing is spawned or boxed per future.
- Added `join_all`: does the same for a collection of futures and returns the results in input order, not finishing order.
- Added `JoinHandle`: an owned handle to a spawned task. Dropping it cancels the task.
- Added `oneshot`, `mpsc`, `watch`: single-threaded channels for passing values between tasks.
- Added `Notify`, `Semaphore`: wake-up and permit primitives for coordinating tasks.
- Added `OnceCell`, `Shared`: compute a value once, or share one future's result between many awaiters.
- Added `Stream`, `StreamExt`: a minimal stream trait with combinators.
- Added `Latest`: keeps only the newest result of overlapping async work.
- Added `retry`, `retry_when`, `Backoff`: retry a failing future with a backoff policy.
- Added `FutureExt`: extension methods on futures.
- Added `next_frame`, `on_idle`, `run_in_phase`: hop a task to a chosen frame phase.
- Added `run_until`, `run_until_stalled`: drive Venus without an event loop, for tests and tools.

### Remote control and capture

- Added `aimer_prendre`: sends synthetic input to a running **debug** app, so a tool or an agent can drive it. A release build never starts the server. It is two Cargo features, `client` (no dependencies) and `host`.
    - The gesture builders in `aimer_prendre::actions` have `_with` forms (`click_with`, `drag_with`, `scroll_with`, `mouse_move_with`) that hold modifier keys through a whole gesture, any number of ctrl, shift, alt and meta at once. `Modifiers` parses from text (`"ctrl+shift"`, `"cmd,option"`) and `modifiers_of` joins a list of names. The wire format already carried `mods=` on pointer commands.
    - Every event a person or the system can cause from outside the process has a command: pointer, touch, scroll, pinch, rotate, pan, keys, text and IME preedit, back, links, menu shortcuts and file drops.
    - The protocol is one text line per command over TCP, guarded by a random per-run token. `AIMER_PRENDRE=1` starts the server; `Config::bind` and `AIMER_PRENDRE_BIND` choose the address, for reaching an app on a phone.
    - The mouse **glides** along a curved, eased path to its targets instead of jumping, and a command sent mid-glide retargets it. Clicks, drags and scrolls glide too; a scroll takes an optional position, and without one scrolls where the mouse is.
    - `scroll` is a smooth **trackpad-style swipe**, which the framework treats as a trackpad and not as a wheel.
    - `typing` types one keystroke at a time at an uneven, human pace. `text` is still one instant edit.
    - `down` and `up` take no coordinates to mean "where the mouse is now", and `actions::click` takes an optional point.
    - `screenshot` returns a picture of the window as a PNG or JPEG, at the window's logical size by default so a point in it is a point that can be clicked.
- Added `aimer_capture`, in `content/`: `screenshot()` takes a picture of the app's window and `Image` encodes, crops and scales it. The `Capture` widget and its `CaptureHandle` pick out the part of the window a child covers. It is behind the umbrella crate's `capture` feature. Only the Metal renderer can copy a frame so far; the others answer `Unsupported` at once.
- Added `aimer_platform::capture` and `aimer_platform::attachment`: a request slot for a picture of the window, and the list of who is connected to the app. The list tells the tool that launched the app (`Role::Launcher`) from an agent that is controlling it (`Role::Agent`); a client that does not say is an agent.
- The debug overlay shows when an agent is controlling the app: a pill badge with the `square-mouse-pointer` icon in the top-right corner, and a cursor, a finger ring and a press ripple where each injected pointer is, so a screenshot shows what the agent did. They fade in when an agent connects and out when the last one leaves. The cursor sways slightly when it rests. Debug builds only.

## Improvement

- Scrolling feels better on Linux.
- Paused video costs nothing per frame.
- Faster gradients.
- Faster `aimer::thread_local`.
- Optimized the Venus runtime.
- Optimized animation performance.
- Scrolling a long list no longer derives the geometry of rows that are out of view.
- Larger Markdown cache capacity.
- Windows: shaders can now be pre-compiled.
- The `image`, `png` and `fdeflate` crates and `aimer_capture` are optimized in the dev profile, so a screenshot encodes in tens of milliseconds instead of over a second.
- The debug overlay shows more accurate information.
- The `Element` family is now documented.
- Text fields hold a long text (from 256 KB) as a rope, so an edit no longer copies the text: typing into a 50 MB note takes about a millisecond where it took over a hundred, an undo step costs the edit and not the note, and a single line of megabytes no longer takes seconds to open or to type in. A short text is stored and edited as before.
- The live markdown preview (`aimer_markdown::LivePreview`, `live_preview`) styles and embeds only the part of a long note that is on screen: typing in a 30 MB note costs about a millisecond of styling instead of the parse of the note. A text field with a windowed highlighter or embedder no longer reads its whole text to find where the cursor's lines are.
- A text field may be up to 16 million logical pixels tall (it was 8 million), which is a note of about 30 MB of short lines.
- Loading a long text costs less memory: a rope took 30% more than its text (its 8 KiB chunks spilled into the next allocator size class, now 8 KiB less 64 bytes), a paste of megabytes was copied three times before it reached the rope, and `on_changed` was given a second copy of the text. Reading the text of a long field out as a `String` is made at its size.
- Pasting and copying a long text no longer copies it through a `String`. On macOS a paste is read as the bytes the pasteboard delivered, and the field's text holds slices of them (an edit copies only the chunks it touches); a copy writes the selection's chunks straight into the pasteboard's buffer. A 30 MB paste costs about 70 MB less memory. Other platforms read and write as before, with one copy fewer than before into the text.
- Opening a long text that is not plain ASCII is much faster: its graphemes are counted without the Unicode rules wherever every character stands alone (Latin, Greek, Cyrillic, CJK ideographs, ...), so a 30 MB note of mixed Latin, Cyrillic, Vietnamese and Chinese opens in about half a second where it took many seconds. `aimer_simd::kernels::simple_grapheme_count` is the kernel; anything that may join (combining marks, emoji, Hangul, Indic scripts) is still counted by the full rules.
- A text field with no `on_changed`, `on_submitted`, `on_focus` or `on_blur` callback no longer copies its text to call it.

## Changes

- **Breaking:** the v2 draw commands are now the framework's only drawing API. The `Drawable` paint hooks were renamed, and `update_retained` overrides that only repeated `update` were dropped.
- **Breaking:** stateful widgets. See [Migrating stateful widgets](#migrating-stateful-widgets).
- **Breaking:** the child views moved from `EventElement` to `VisitorElement`, so one trait now answers which children an element has: `event_children`, `structural_children`, `focus_children`, `hit_test_children`, `hit_test_children_reversed`, `hit_test_children_at`, `hit_test_children_at_reversed` and `occlusion_children_at`. Their defaults and meanings are unchanged, and calls such as `element.event_children(..)` still work. An element that overrides one of them moves that method from its `impl EventElement` block to its `impl VisitorElement` block; the compiler reports each one as "not a member of trait `EventElement`".
- **Breaking:** `Element` is no longer implemented automatically. `VisitorElement::debug_name` moved to `Element::name` and is now the only required method of the element family, so an element writes `impl Element for T { fn name(&self) -> &'static str { "T" } }` next to its other `impl`s. The compiler reports each old definition as "not a member of trait `VisitorElement`"; `Widget::name` is unchanged.
- **Breaking:** `TextEditingValue::text()` returns a `Cow<'_, str>` instead of a `&str`: borrowed for a short text and a copy of all of it for a long one. Code that only reads it works as before; code that needs a `String` calls `.into_owned()` (`.to_owned()` now gives another `Cow`). `TextEditingValue::slice(range)`, `len()` and `is_empty()` read a part of a long text without the copy.
- Added the `aimer_sum_tree` and `aimer_text_buffer` crates (`cores/`): a persistent B+tree with summaries, and a rope text buffer with snapshots, edits, undo, a layout index for very long lines, and anchors. `aimer_input` uses them for long texts.
- Added `aimer_clipboard::clipboard::{get_shared_text, set_text_chunks, ClipboardText}`, and `aimer_text_buffer::{SharedText, TextSnapshot::from_shared, TextSnapshot::with_replaced_snapshot}`, which make a rope whose chunks are slices of a text held elsewhere.
- Added `TextEditingValue::with_str`, `TextEditingController::with_str` (a controller from borrowed text, with no `String` made of a long one), `TextEditingValue::same_text` and `TextFieldCallback::call_owned`.
- **Breaking:** `EventTreeRole::Legacy` is gone. It was an alias of `IndexedHitTestBoundary`; use that role.
- **Breaking:** an element is now registered in the event tree only when it says it handles events. The default `EventElement::event_tree_role` is `Transparent` (it was `IndexedHitTestBoundary`), so a wrapper or a painting leaf costs event routing nothing. An element that overrides `on_event`, `on_event_with_context` or `focus_node`, or that narrows hit testing with `hit_test_children` or one of its variants, must now override `event_tree_role` too, or the dispatcher never reaches it; `IndexedHitTestBoundary` gives it what it had before. A retained child whose element handles nothing and has no event children below it no longer adds a target either.
- Event routing no longer has a walk of its own for children that are missing from the event tree. Such a child now trips a debug assertion naming the element, and receives nothing in release builds. Nothing in the tests or in the showcase reached that path.
- Graphic backends moved into `graphic/backends/`, and the `window` crate moved from `host/` to `native/`.
- Removed the experimental feature flag.
- Added the `content/capture` crate, and `aimer_prendre` and `aimer_capture` to the workspace dependencies.
- Removed the old `jaime` app from the repo.
- Added the `polymorphism` experiment crate.
- Added the `stateful_widget_2` experiment crate: a backend-independent consistency suite for stateful implementations, run against the framework and against a copy of the old machinery, plus a std-only mock of the new design.
- The nested-chain cost of stateful rebuilds is pinned by tests in `aimer_widget_core`, for unkeyed and for keyed chains.
- The Android manifest in `jaime` now uses the new format.
- The Apple Xcode projects now link AVFoundation and CoreMedia.

### Migrating stateful widgets

A counter, before and after:

```rust
// Before
#[derive(StatefulWidget)]
pub struct Counter {
    pub start: i32,
}

pub struct CounterState {        // had to be `pub`: `type State` named it
    updater: StateUpdater<Self>, // every state stored its own updater...
    count: i32,
}

impl StatefulWidget for Counter {
    type State = CounterState;

    fn create_state(self) -> CounterState {
        CounterState { updater: StateUpdater::empty(), count: self.start }
    }
}

impl State<Counter> for CounterState {
    fn init_state(&mut self, updater: StateUpdater<Self>) {
        self.updater = updater;  // ...and forgetting this line panicked on first use
    }

    fn build(&self, _ctx: &BuildContext) -> impl Widget {
        let updater = self.updater;
        let _increment = move || updater.set_state(|state| state.count += 1);
        Text::new(format!("Count: {}", self.count))
    }
}
```

```rust
// After
#[derive(StatefulWidget)]
#[state(CounterState)]
pub struct Counter {
    pub start: i32,
}

struct CounterState {            // private is fine now, and there is no updater field
    count: i32,
}

impl State<Counter> for CounterState {
    fn create(widget: Counter) -> Self {
        Self { count: widget.start }
    }

    fn build(this: StateView<Self>, _ctx: &BuildContext) -> impl Widget {
        let updater = this.updater();
        let _increment = move || updater.set_state(|state| state.count += 1);
        Text::new(format!("Count: {}", this.count))   // fields are read through `this`
    }
}
```

Steps:

1. Add `#[state(YourState)]` to the widget, and delete the `impl StatefulWidget` block. Its `create_state(self)` body becomes `State::create(widget: YourWidget) -> Self`, with `self.` becoming `widget.`.
2. Delete the `updater` field, its initializer and the `init_state` line that stored it. If `init_state` has nothing else in it, delete it.
3. Change `fn build(&self, ctx)` to `fn build(this: StateView<Self>, ctx)`. `self.field` becomes `this.field`, and `self.updater` becomes `this.updater()`.
4. If a state's own `&self` helper methods read `self.updater`, pass `this.updater()` to them as a parameter. If that is not practical, keep an `updater` field and set it in `on_mount`.

An `init_state` that hands the updater to something that outlives the call becomes `on_mount`:

```rust
// Before
fn init_state(&mut self, updater: StateUpdater<Self>) {
    self.back_guard = Some(back::register(NavigatorBack { updater }));
}

// After
fn on_mount(&mut self, updater: StateUpdater<Self>) {
    self.back_guard = Some(back::register(NavigatorBack { updater }));
}
```

`on_mount` runs after `init_state`, so anything it relies on that `init_state` sets up is in place. Prefer `try_set_state` and `try_read` in what you register: it can run after the element is gone.

A widget with a hand-written `Widget` impl names its state in the call, which is also what lets the state stay private:

```rust
// Before
```

Tests that built a state directly:

```rust
// Before
let state = widget.create_state();

// After
let state = widget.create_state::<CounterState>();
let element = state.build_element(&ctx);
```

A test that grabbed the updater in `init_state` to drive the state from outside publishes it from `build` instead, with `this.updater()`.
- **Breaking:** `StateView` no longer borrows the state. It holds the same generation-checked slot handle as `StateUpdater`, so it is `Copy + 'static` and a `move` closure can capture `this` and call `this.set_state(..)`, `this.read(..)` or read `this.field` when it runs. It lost its lifetime parameter (`StateView<'a, S>` is `StateView<S>`; `build` now takes `this: StateView<Self>` by value instead of `&StateView<Self>`; the value is `Copy`, so a body that only uses `this` is unchanged, but the widget `build` returns can no longer borrow from `this`). `this.field` now looks the slot up and panics once the element is gone, about 25 ns per read in a debug build against about 3 ns for a plain reference; bind a field read many times in one build to a local. `StateView::detached` is now `unsafe`. `StateView` also forwards every `StateUpdater` method (`set_state`, `set_state_with`, `try_set_state`, `read`, `try_read`, `read_state`, `try_read_state`, `has_state` and the unchecked pair).
